## 最後に直したもの

- `src/engine/project/ProjectIO.ts`: 参照だけのプロジェクト (.wgpj) を開くとき、このページで前に開いたファイルの覚え (`known`、名前と大きさだけ) を MME のフォルダのファイルにも使っていたため、同じページで「Ray-MMD を使うプロジェクト A を開く → 別のプロジェクトを開く → A を開き直す」と、名前も大きさも同じで中身の違う Ray-MMD のファイル (1.5.2 に 144 組) が 1 つにまとまっていた。MME のファイルは、フォルダの名前・パス・大きさで覚えて探すようにした。選んでもらったファイルに相対パスがないときも、同じ名前・大きさのものが 2 つ以上ある MME のファイルは名前で当てない (取り違えるより、見つからないほうにする)。

## 次に回したこと

### 第 3 の計画 (割り当ての残り・UI)
- 割り当ての画面: .fx の選択肢を行ごとに作り直している (Ray-MMD は 600 以上)。選んだものを表示の文字で照らし合わせている。タブの aria、既定の欄の aria-describedby、同じ名前の物のラベルの重なり、長い名前のはみ出しのテスト
- 仮のコントローラー: 項目名の大文字小文字をまとめていない、bool の項目のスライダーがない、キーフレーム
- ステージを差し替えても、ステージの割り当てが残る
- `used` (保存するファイル) から、もう使わないファイルを取り除かない
- .x アクセサリ・.emm・MCP のコマンド・`fx/` の一覧 (もともとの第 3 の計画)

### 第 5 の計画 (ほかの MME エフェクト・細かいこと)
- DDS: 古いマスクの形式 (A8・24 ビット・BC4/BC5・X8B8G8R8)、L8/A8L8 を D3D と同じ (L,L,L,A) で読まない、`.hdr` の型の決め打ち
- 浮動小数点のテクスチャで MipFilter を使うと、GL にミップを作らせる (32F・.hdr は線形補間できない)
- `pow(abs(x), y)` は、負の数を奇数の整数乗するときに fxc と違う。定数の `normalize(0)` は NaN のまま。D3D9 の 0×∞=0 は `normalize` だけ
- 書き換え表の行は短くなる (その行の列がずれる)
- オフスクリーン: 入れ子の深さが順番で変わる、自分を読むオフスクリーンは GL のフィードバックになる、GPU の資源を捨てるのが 2 フレーム遅れる
- `Framebuffers`: 止めたエフェクトがほかの shared の枠を取り続ける、描き先を替えるたびにミップを作り直す、shared のサンプラーの設定が食い違っても警告しない
- 1 フレームの重さ: CONTROLOBJECT ごとに物と骨を探す、形ごとに Matrix4 を作る、材質の変更のたびに割り当ての行を作り直す
- `DefaultEffect` の `self` の規則は、保存するファイルを決めるときにすべての名前で数える (少し多めに保存する)
- 開く途中で自動保存の予約が入る (最後に上書きされるので害はない)
- テストの穴: preprocess とオフスクリーンの組み合わせ、オフスクリーンの中の `(self)`/`(OffscreenOwner)`、`light()` の大きさと overlay の near/far の戻し方、`parts()` の hide
- 関係のない不安定なテスト: `e2e/cloner.spec.ts:150` (MoGraph。`waitForTimeout(50)`)
