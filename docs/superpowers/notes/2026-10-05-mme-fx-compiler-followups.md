## 次に回したこと

### 第 2 の計画 (ランタイム) を始める前に読む
- `ARCHITECTURE.md` の core/fx の注意書き (`mme_flipY` で巻き方向が変わる、`mme_viewport`、`a_`/`v_`/`o_COLORn`、行列は D3D の並びのまま `transpose=false`、配列の配列は平ら)
- `Program.uniformVectors` は 2 つのシェーダーを合わせた数。WebGL の上限はシェーダーごとなので、ランタイムで分けて数える
- 半ピクセルのずれと、いつ上下を返すかはランタイムが決める

### 第 5 の計画 (ほかの MME エフェクト) で、`fx:check` の結果を見て直す
- 再帰する関数を `ok: true` で通してしまう (GLSL も fxc も再帰を許さない) → 未対応にする
- サンプラーを返す関数は、正しくない GLSL になる
- スカラーの `&&`・`||`・`?:` は GLSL では短絡する。被演算子に副作用やテクスチャのサンプリング (暗黙の微分) があると、HLSL と違う
- 偽の `#if` の中や `#error` の文に、字句にできない文字 (日本語・アポストロフィ) があると止まる (ファイル全体を先に字句にするため)。`#pragma once` を見ていない
- 注釈の閉じの `>` のあとに空白なしで `=` が続く (`<…>= 1`) と読めない
- 行末の `\` のあとに空白があると、行をつながない
- 配列の配列の初期値は、すべて `{ }` で区切るか、要素ごとに平らに並べるかのどちらかだけ
- vs_2_0/ps_2_0 の COLOR を [0, 1] に収める動きは再現していない
- `check.ts` は約 1000 行。増えるなら式の型付け (`infer*`) を別のファイルに分ける
- 名前を付け替えた結果が、ユーザーの名前とぶつかる可能性がある (`input` → `input_` と、もともとの `input_`)
