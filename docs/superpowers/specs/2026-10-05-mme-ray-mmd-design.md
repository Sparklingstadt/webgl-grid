## 目的

Ray-MMD 1.5.2 の標準の構成に、ライトとフォグを加えたものを、レンダーエンジン「MME 互換」で動かす。この計画の終わりには、次のことができる。

- ray.fx をポストエフェクトにし、モデル（の材質ごと）に `material_2.0.fx` などの材質の .fx を割り当て、空・ライト・フォグの .pmx を置くと、Ray-MMD の絵がビューポートの「レンダー」表示と書き出し（PNG・動画）に出る。
- その割り当てと設定がプロジェクトに保存され、開き直すと同じ絵になる。

## 決めたこと

- 合格の線は **「標準の構成＋ライトとフォグ」**: ray.fx・コントローラー・空・材質の .fx に加えて、`LightMap`（Lighting フォルダのライト）と `FogMap`（Fog フォルダのフォグ）も動かす。
- Ray-MMD のバイナリ（.pmx・.dds・画像。1.5.2 のタグで 263 ファイル・約 84 MB）は、GitHub（ray-cast/ray-mmd のタグ 1.5.2）から取ってきて、Git に入れない `fx/ray-mmd-1.5.2/` に置く。手元の e2e と目で確かめるのに使う。CI は自作の小さなファイルだけで確かめる。**取ってくる前に、ファイル名・出所・大きさをもう一度確認する。**
- 割り当ては **タブごと・物ごと・材質ごと** にでき、**プロジェクトに保存する**。
- **値を渡すためだけのバイナリは読まない。** `ray_controller.pmx`（と `_plus`・`_minus`）や `ray.x` は、.fx が値を読むためだけにあるので、MME の欄のスライダーで値を入れる。ray.fx はアクセサリの値を読まないので、`ray.x` なしでポストエフェクトとして足す。
- ライト・フォグ・空の .pmx は、形も使う（点光源は球の法線から光の範囲を作り、空は箱やドームに描く）ので、いままでどおり読み込む。
- 作り方は **「場面を描く」処理を 1 つにまとめ、割り当て表とターゲットを替えて使い回す**（画面もオフスクリーンも、入れ子のオフスクリーンも同じ処理）。
- 合格は、手元の Ray-MMD で「未対応」の警告とリンクの失敗が 0 で書き出せることと、Ray-MMD の見本の画像（`Shader/screenshots`）と目で比べておかしくないこと。最後の目の確認はユーザーが行う。ビューポートの速さは合格の条件にしない（測って README に書く）。

## 部品

### `core/mme/`（純粋な計算。WebGL なしで単体テストする）

| `technique.ts`（広げる） | テクニックを MME の決まりで選ぶ: `MMDPass`・`Subset`（材質の番号の範囲 `"0-3,5"`）・`UseTexture`・`UseSphereMap`・`UseToon`・`UseSelfShadow` |

| `dds.ts` | DDS を読む（ヘッダー・DX10 の拡張ヘッダー・形式・キューブマップ・ミップの並び）。実装の最初に配布物のすべての DDS を調べ、出てくる形式をすべて読む |

### `engine/mme/`（three.js を使う部分）

| ファイル | 中身 |
|---|---|

| `Offscreen.ts` | `OFFSCREENRENDERTARGET` を持つエフェクトごとに、そのタブの割り当て表を作り、ターゲットに描く。`ClearColor`・`ClearDepth`・`AntiAlias`・形式・大きさの注釈を読む。入れ子（ライトの .fx の中の影のオフスクリーン）は、同じ処理をもう一段呼ぶ。`OffscreenOwner` は、そのオフスクリーンを持つ物を指す |

| `Controllers.ts` | `CONTROLOBJECT` の値を作る。場面にある名前・`(self)` はそのモデルのモーフ・骨・ワールド行列から、場面にない名前は仮のコントローラーのスライダーの値から |
| `EffectStore.ts`（直す） | フォルダの文字のファイル（.fx・.fxsub・.conf・.fxh）だけを先に読み、画像は使うときに `File` から読む。読んだファイルを記録する（.wgp に入れるため）。同じ .fx・同じ `#define` のコンパイル結果を使い回す |
| テクスチャの読み込み（直す） | DDS は `core/mme/dds.ts` で読む。`.hdr` と `.tga` は three.js の読み込み（`HDRLoader`/`RGBELoader`・`TGALoader`）、`.bmp` はブラウザの読み込み |

`MmeRenderer` は、ScenePass・Offscreen・PostChain を順に呼ぶだけの薄いものにする（第 2 の計画で 700 行近くになったものを分ける）。

### 画面（`ui/`）

- MME の欄に「エフェクト割当」のタブ: 「Main」と、読み込んだエフェクトが宣言したオフスクリーン（名前。`Description` を説明に出す）。

- 物ごとの割り当ては、物ごとの値（`objectData` の `mme`）にする。保存・複製・取り消しは、いまの仕組みでそのまま扱われる。

## 1 フレームの流れ

1. 骨とモーフの変形を、描く物すべてについて 1 回計算する。
2. 仮のコントローラーと `CONTROLOBJECT` の値を集める。
3. `ScriptOrder` が `preprocess` のエフェクトを描く。
4. オフスクリーンを、宣言の逆の順に描く（Ray-MMD は後に宣言した `MaterialMap` が書く G バッファを、先に宣言した `LightMap`・`FogMap` が読むため。それぞれ、そのタブの割り当て表で ScenePass を呼ぶ。入れ子は、そのオフスクリーンの中で先に描く）。同じフレームの中で、オフスクリーンは 1 回だけ描く。
5. Main の割り当て表で場面を描き（`standard`）、ポストエフェクト（`postprocess`）の連なりに渡す。ここは第 2 の計画のまま。

## MME の値と決まり（この計画で足すもの）

### 物の名前

`DefaultEffect` と `CONTROLOBJECT` の名前は、MMD のモデルなら .pmx のファイル名（例 `PointLight.pmx`）、それ以外の物（形など）は物の名前で照らし合わせる。同じ名前の物が複数あるとき、`CONTROLOBJECT` は MME と同じく最初の 1 つを読む。

### `CONTROLOBJECT`

| 項目 | 値 |
|---|---|
| なし（`float4x4`） | 物のワールド行列（MMD の座標） |
| なし（`float3`/`float4`） | 物の位置 |
| `bool` | 物があって、表示されているか |
| 骨の名前（`float3`/`float4`/`float4x4`） | 骨の位置・ワールド行列 |
| モーフの名前（`float`） | モーフの値 |

`(self)` は、そのエフェクトを割り当てた物。アクセサリの項目（`X`・`Si`・`Tr` など）は、.x を読まないので、仮のコントローラーにも出さない（0 と警告）。仮のコントローラーは、場面にない名前ごとに作り、モーフの名前の項目（`float`）だけをスライダーにする。そのほかの型の項目は 0 と警告。

### `shared`・テクニック・`ScriptOrder`

- `shared` のテクスチャ: 上の `SharedTextures.ts`。`MaterialMap` などで ray.fx と材質の .fx が同じものを使う。
- テクニック: `techniques[0]` をやめ、上の `technique.ts` で選ぶ。合うものがなければ、その pass は描かない（MME と同じ）。
- `ScriptOrder`: `STANDARDSGLOBAL` の `ScriptOrder`（`standard`・`preprocess`・`postprocess`）で描く順を決める。

### レンダーターゲット

- 形式: Ray-MMD が使うもの（`A8R8G8B8`・`A16B16G16R16F`・`A32B32G32R32F`・`R16F`・`R32F`・`G16R16F`・`G32R32F`・`D24S8` など）。実装の最初に Ray-MMD のすべての宣言を集めて、表にする。
- ミップ: `MipLevels`（0 はすべての段）。`MipLevels` が 1 でないターゲットは、描き終えたあとにミップを作り直す（MME の自動ミップと同じ）。
- `Clear=Depth` は、深度と一緒にステンシルも消す（第 2 の計画で残した直し）。

### 時間

`TIME` と `ELAPSEDTIME` は、タイムラインの時間（コマ ÷ fps）から作る。`SyncInEditMode` に関わらず、実際の時計は使わない（書き出すたびに同じ絵になるように）。止まっているときの `ELAPSEDTIME` は 0。

### この計画で入れないもの（警告を出して止める）

- `ANIMATEDTEXTURE`（GIF の動画の材質。`Materials/Video`）
- アクセサリ（.x）とその項目

## 保存

`sceneData` の `'mme'` に足す:

- 読み込んだ .fx のフォルダ（id と名前）。中のファイルは、そのプロジェクトで実際に読んだもの（.fx・include・画像）を、モデルのファイルと同じくプロジェクトのファイル（assets）として持つ
- タブごと・物ごと・材質ごとの割り当て（物ごとの値として、物のデータに入る。フォルダの id と .fx の相対パス、または「非表示」）
- ポストエフェクトの並び（フォルダと相対パス）
- 仮のコントローラーの値（名前 → 項目 → 値）

開くとき:

- 参照だけ（.wgpj）: このページで読んだファイルから探し、なければ、モデルのファイルと同じく、探してもらう画面を出す（フォルダを選べば、名前と大きさで照らし合わせる）。見つからなければ、割り当ては残したまま、そのエフェクトは描かない。
- ファイルも入れる（.wgp）: 実際に読んだファイルだけを入れる。保存の前に、割り当てたエフェクトの画像を読み終えるまで待つ（まだ描いていなくても入るように）。
- 開き直したあと、まだ読んでいないファイル（新しく足すライトの .fx など）が要るときは、同じフォルダをもう一度読み込む（同じ名前のフォルダは 1 つにまとめる）。

物ごとの割り当ては、物ごとの値（`objectData`）として持つので、複製で写り、取り消し（Undo）の対象にもなる。フォルダ・ポストエフェクトの並び・仮のコントローラーの値は場面の値で、取り消しの対象にしない（いまの出力の設定と同じ）。第 2 の計画の「新しいプロジェクト・プロジェクトを開いたときは割り当てを外す」は、「開いたプロジェクトの割り当てにする」に変わる。

## エラーの扱い

いまの決まりを広げる。

- 未対応の機能を使う .fx は、その .fx だけを止め、理由を警告に出す。オフスクリーンのタブで止まった物は、そのタブでは描かない。
- 浮動小数点のレンダーターゲットが使えない環境では、それを使うエフェクトを止め、理由を出す。
- 見つからない画像はマゼンタにして警告（いまのまま）。
- 割り当てた物が消えたら、その割り当ても消す。割り当てた .fx がフォルダにないときは、警告を出してその行を既定に戻す。
- 警告はすべて t() を通す（日本語・英語・簡体字・繁体字）。

## 重さ

- Ray-MMD は 1 フレームに場面を 10 回以上描く。骨の変形は 1 回だけにし、コンパイル結果を使い回す。ビューポートの fps は合格の条件にせず、測って README に書く。
- 大きなフォルダ（Ray-MMD 全体で約 84 MB）は、文字のファイルだけを先に読む。

## 合格の基準

1. Ray-MMD 1.5.2 の標準の `ray.conf` で、ray.fx（ポストエフェクト）・モデルに `material_2.0.fx` と材質ごとの .fx（肌・髪・服など）・空（Time of day）・Lighting フォルダのすべての種類のライト（`Default` の .fx）・Fog フォルダの 4 種類のフォグが、「未対応」の警告とリンクの失敗なしに動き、PNG と動画に書き出せる。
2. 点光源・スポットライト・グラウンドフォグ・空を入れた絵を、Ray-MMD の見本の画像と目で比べて、おかしくない（最後の確認はユーザー）。
3. 標準のレンダーエンジンの絵と、第 2 の計画までのテストは変わらない。
4. 割り当てと設定を保存して開き直すと、同じ絵になる。

## 実装でわかったこと

本物の Ray-MMD 1.5.2（`fx/ray-mmd-1.5.2/`）を、標準の構成（`ray.conf` のまま）＋ライト 10 種類＋フォグ 4 種類＋空（Time of day）で読み込んで確かめた（`e2e/ray-mmd-local.spec.ts`）。

- 「未対応」の警告として出たのは、サンプラーの `SRGBTexture = TRUE`（`Shader/LTC.fxsub` の LTC の表。rgba16f の .dds）だけだった。8 ビットの RGBA の画像は sRGB の写しにして GL に線形にさせ、浮動小数の画像は D3D9 と同じく何もしないことにした。残る警告は、`AddressU/V = BORDER` を `CLAMP` にする（GL にない）・同じレンダーターゲットを違う設定のサンプラーで読む（最初のサンプラーの設定にする）・コンパイラの `float4 を float3 に切り詰めます` で、どれも近似の知らせ。リンクの失敗・止めたエフェクトは 0。
- **サンプラーの `BORDER`（決めたこと。Ruling 17）**: わざと `CLAMP` で近似したままにする（警告は出す）。WebGL2 には `CLAMP_TO_BORDER` がなく、まねるにはサンプラーを読む所ごとにシェーダーを書き換える必要があるため。そのぶん、Ray-MMD のブルーム（`BloomSamp*`）で、絵の端の色が少しにじむことがある。
- オフスクリーンのタブは 9 つ（FogMap・LightMap・EnvLightMap・MaterialMap・SSAOMap・PSSM1〜4）。ライトの .fx は `LightMap` の `DefaultEffect` で種類ごとのフォルダの `Default/`（LED は `Default LED/`）のものが、フォグの .fx は `FogMap` の `DefaultEffect` で種類ごとのフォルダのものが選ばれる。PNG と動画に書き出せる。1280×720 で 1 フレーム 13.7 ms 前後（Apple M3 Max。Task 16 のあとに測り直した。Task 15 では 13.5 ms）。
- **座標の大きさ（決めたこと。Ruling 15、Task 16）**: Task 15 では、MME に渡す世界がこのアプリの世界（MMD の単位の 0.1 倍）のままで、MMD モデルの `WORLD` に 0.1 倍と置いた場所が入っていた。MMD ではモデルの `WORLD` はふつう単位行列なので、Ray-MMD の一部は頂点の位置をそのまま世界の位置として使い（`Shader/PSSM.fxsub` の影の深さ、`Time of day.fx` の空の球）、場面が影で真っ黒になり、空の球（半径 10000）はカメラの遠い面（1000）の外だった。そこで、MME の空間を MMD の単位にした（k = 1 / `MMD_SCALE` = 10。`MMD_UNITS`）:
  - MMD モデル（置いた物とステージ）は `WORLD` を単位行列にし、`Skinner` が置き方を頂点に入れる（`p = S · k · matrixWorld · p_local`、S = diag(1, 1, −1)。法線は回すだけ。骨・モーフ・置き方のどれかが変わったときだけ作り直す）。輪郭線は MME の空間のカメラで広げる。
  - ほかの物（形など）は `WORLD = toMmd(Scale(k) · matrixWorld)`。
  - カメラは位置と注視点を k 倍（向きはそのまま）、近い面を k 倍、遠い面を `max(遠い面 × k, 100000)`（`mmeCamera`）。MME の深度に重ねる編集用の表示は、three.js のカメラの近い面・遠い面を MME のカメラの 1/k にして描き、戻す（深度の値がそろう）。
  - ライト・`CONTROLOBJECT` の位置と行列も k 倍。太陽の影のカメラは位置・範囲・近い面・遠い面を k 倍にするので、深度マップの値と「影の距離」（MMD の値。既定 8875）の意味は変わらない。地面の影は MMD の単位で 0.1 持ち上げる（前と同じ高さ）。ライトの `POSITION` は注視点から 10000。
  - 第 2 の計画までの e2e は変わらずに通る。値の変わった単体テストは、`coords`（地面の影の持ち上げ 0.01 → 0.1）・`semantics`（同じ）・`Controllers`（位置と行列が 10 倍）・`Skinner`（テストのモデルを読み込んだモデルと同じく 0.1 倍で置いた）と、e2e の `mme-controllers`（骨の位置を MMD の単位で色にする）・`mme-offscreen`（`WORLD` の原点ではなく頂点の位置で左右を見る）。
- **空とステージ（決めたこと。Ruling 16、Task 16）**: 空の .pmx（Time of day は一辺 20000）は大きいので、読み込むとステージになる。置いた物にすると、積み重ねでほかの物が上に乗る（か空が上に乗る）。そこで、ステージも置いた物と同じく割り当てられるようにした: 割り当ては場面の値 `MmeScene.stage`（`ObjectEffects`。保存・開く・最初の状態で消える。ポストエフェクトと同じく元に戻すの対象にしない。ステージを差し替えても残る）、決め方は材質 → 物 → `DefaultEffect`（.pmx のファイル名）→ Main では `default.fx`、ステージを描くときの `(self)` とステージの .fx が宣言したオフスクリーンの持ち主はステージ（`Owner = Obj | STAGE | null`）、エフェクト割当のどのタブにも「ステージ: .pmx のファイル名」の行（材質の行つき）を出す。手元の e2e は空をふつうに読み込んでステージにし、`README.png` のとおりに割り当てる。ステージは 1 つだけなので、会場のステージと空のステージは同時に使えない。
- **肌・髪の材質（Task 16 で直した）**: `Materials/Skin/material_skin.fx`・`Materials/Hair/material_hair.fx` の材質が黒くなっていたのは、座標の大きさとは関係なく、2 枚目の法線マップ（`NORMAL_SUB_MAP_FROM 1`）の接線を UV の微分から作る所（`ComputeTangentBinormalNormal`）で、テストのモデルに UV がない（全部 0）ため `normalize(0)` になり、GL では NaN になっていたため。D3D9 の `nrm` は 0 のベクトルを 0 にする（rsq の ∞ に 0 を掛けると 0）ので、コンパイラの `normalize` を `mme_normalize`（0 なら 0）にした。同じく、D3D9 の `pow` は |x|^y なので `pow(abs(x), y)` にした（Time of day の太陽の縁 `pow(cos(π/2), …)` が NaN になっていた）。
- **空（Time of day）が黒い（残っていること）**: 空の球は描かれ（遠い面の中）、地平線と太陽の向きは合っているが、色が黒い。`Time of day.fx` の大気の式では、Mie 散乱の係数を `ComputeWaveLengthMie(mWaveLength, SunColor, mSunTurbidity)` で作り、既定のモーフ（`SunTurbidity` = 100）と光の色（MMD の既定 0.6）では 1 m あたり約 0.45〜1 になる。この値だと、地上 1 km から見た空の光は大気で全部吸われる（倍精度の JavaScript で同じ式を計算しても 0。係数を 1/1000〜1/3000 にすると明るい空になる）。MMD では明るく見えるはずなので、MME が渡す値（光の色・`CONTROLOBJECT`）の違いなどを疑っているが、まだ分かっていない。空が黒いので `EnvLightMap`（空からの環境光）も暗く、太陽の当たらない面は黒くなる。
- Ray-MMD 1.5.2 の .dds にキューブマップはない。ミップを持つ .dds（`Lighting/SphereLight/Default IBL/texture/skyspec_hdr.dds`、1024×512・7 段）は、GPU で `tex2Dlod` の段ごとに .dds のその段の色が読めることを確かめた。
- Time of day の割り当ては、同じフォルダの `README.png` のとおり、Main に `Time of day.fx`・`FogMap` に `Time of fog.fx`・`EnvLightMap` に `Time of lighting.fx`・`MaterialMap` に `Materials/material_skybox.fx`。モデルの Main には `Main/main.fx`（不透明度 0 を書き、色は G バッファの陰影を使わせる。`default.fx` のままだと MMD の陰影が上に重なる）。
